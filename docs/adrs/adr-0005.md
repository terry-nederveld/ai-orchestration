# Context

Autonomous agents spend real money and finite subscription quotas, and can
loop unboundedly. Providers bill differently: per-token APIs, subscription
request counters (Copilot premium requests), or free local inference. Cost
control bolted on later tends to live in one provider's adapter and leak
vendor assumptions into the kernel.

# Decision

Budgets are a core domain concept. `BudgetLimits` bounds every dangerous
dimension — tokens, estimated USD, subscription requests, iterations,
wall-clock, concurrent agents, sub-agents per run, and provider-specific
quota keys. A pure `BudgetTracker` accumulates consumption and reports
warning (80%) and exhaustion states. Every agent run produces a
`UsageRecord` (provider, model, tokens, estimated cost, subscription
requests where measurable, duration, turns, sub-agents) that is persisted
and aggregated per period (run/day/week/month). The runtime halts a session
with `BUDGET_EXHAUSTED` the moment any dimension is exhausted; budget events
(`budget.warning`, `budget.exhausted`) flow through the event bus.

# Rationale

- Bounding iterations and wall-clock in the runtime is the only reliable
  defense against agent loops; provider-side limits can't see our loop.
- Provider-specific quota keys (`providerQuotas`) let subscription services
  express request-counting without the kernel knowing vendor names.
- Cost estimation is deliberately injected (a `costEstimator` function fed
  by model pricing metadata) so the tracker stays pure and testable.

# Alternatives Considered

- **Per-provider limits only** — leaves the kernel unable to answer "what
  did this run cost?" across providers; rejected.
- **Hard USD ceilings only** — subscription consumption isn't USD-shaped;
  both dimensions are needed.

# Consequences

- Positive: sub-agents are metered resources (count and depth limited);
  runs expose full consumption for the UI; automatic cheapest-suitable
  routing has the data it needs later.
- Negative: estimated cost is an estimate — pricing tables drift; records
  mark estimates as such and subscription consumption as "where
  measurable".

- packages/core/src/budget.ts; enforcement in packages/runtime.
- Wall-clock uses max-not-sum semantics when recorded incrementally.

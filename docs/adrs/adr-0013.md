# Context

Users legitimately consume models two ways: API keys (pay per token) and
subscriptions (Claude Pro/Max, ChatGPT, Copilot seats). Research (August
2026) established what each vendor officially supports programmatically:

- **Claude Code / Agent SDK** (`@anthropic-ai/claude-agent-sdk`): API key is
  the sanctioned SDK auth. Subscription OAuth via `claude setup-token`
  exists, but Anthropic's docs prohibit third parties from offering
  claude.ai login/rate limits in their products without approval.
- **Codex** (`@openai/codex-sdk` wrapping the `codex` CLI): ChatGPT sign-in
  (browser OAuth or device-code flow) and `OPENAI_API_KEY`; OpenAI guidance
  steers programmatic/CI use to API keys or Enterprise-issued
  `CODEX_ACCESS_TOKEN`s.
- **Copilot** (`copilot` CLI, `@github/copilot-sdk`): OAuth device flow
  interactively; headless via `COPILOT_GITHUB_TOKEN`/`GH_TOKEN` (documented
  for CI), plus `gh` CLI token fallback and BYOK.

# Decision

1. Authentication is a composable strategy attached to provider configs,
   not embedded in adapters: `api-key` (secret store), `cli-session`
   (delegate to the vendor's own locally authenticated CLI/SDK),
   `device-code`/`oauth` (vendor-run flows we invoke), `cloud-credentials`.
2. Overture never implements a vendor's consumer login itself, never
   scrapes cookies, and never calls private auth endpoints. Subscription
   consumption is supported exclusively by **delegating to the vendor's own
   tooling that the user has already authenticated**: the Claude Agent SDK /
   `claude` CLI using the user's existing login, `codex` using `codex
   login`'s stored auth, `copilot`/`gh` using GitHub's flows. Where a vendor
   restricts subscription use for products (Anthropic's claude.ai-login
   clause), Overture surfaces the vendor's own auth state and terms rather
   than working around them; API-key auth is always offered as the
   compliant default.
3. Provider `detect()` reports installed/authenticated/available and the
   auth kind in use, so the UI can show truthful status ("Claude Code:
   authenticated via subscription CLI session").
4. All tokens/keys live in the secret store (ADR pending packaging of
   @overture/secrets decision — see Implementation Notes); nothing enters
   model context or logs (redaction enforced).

# Rationale

- Delegation-to-vendor-tooling is the only pattern that is simultaneously
  useful (subscription users get value), honest (the vendor's own client
  enforces its terms), and durable (vendor auth changes don't break us).
- Strategy composition keeps new auth mechanisms from touching adapters.

# Alternatives Considered

- **Reimplementing vendor OAuth flows ourselves** — fragile and, for
  Anthropic, explicitly disallowed for products; rejected.
- **API-key only** — compliant but abandons the subscription requirement
  where vendors do support delegation; rejected.

# Consequences

- Positive: truthful capability/auth reporting; ToS-compatible subscription
  paths; secrets never in config files.
- Negative: subscription paths require the vendor CLI installed and
  logged in — represented accurately as a detection state, with setup
  guidance in the UI, not hidden.

# Implementation Notes

- packages/providers/agent-* adapters implement `detect()` by probing the
  vendor CLI/SDK; API keys resolve through SecretProvider at call time.
- ANTHROPIC_API_KEY silently overriding a Claude subscription session is a
  known vendor behavior — adapters must set env deliberately per child
  process, never inherit ambient keys blindly.

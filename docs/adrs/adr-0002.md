# Context

The architecture demands hard boundaries: orchestration kernel, agent
runtime, workflow engine, and every provider family must be independently
replaceable and testable. Boundaries that exist only as folder conventions
erode; boundaries that exist as package dependency edges are enforced by the
compiler and package manager.

# Decision

Use a single pnpm workspace monorepo. Every architectural boundary is its own
private package under `packages/` (providers under `packages/providers/`),
the desktop shell under `apps/`. Tooling: TypeScript project references for
incremental builds, Vitest with workspace projects for tests, Biome for
lint + format.

# Rationale

- Package edges make illegal dependencies (e.g. a work provider importing
  the orchestrator) impossible to express accidentally: `@overture/core`
  has zero dependencies, and adapters depend only on core.
- pnpm's strict node_modules prevents phantom dependencies that would
  undermine the boundary guarantees.
- One repo keeps atomic cross-boundary refactors cheap while contracts are
  still settling.
- Biome replaces ESLint + Prettier with one fast tool; Vitest projects give
  per-package suites with a single root command.

# Alternatives Considered

- **Single package with folder conventions** — simpler plumbing, but no
  enforced boundaries; rejected as directly contrary to the architecture
  goals.
- **Multiple repositories** — maximal isolation but crippling for a
  fast-moving 0.x codebase; contract changes would need synchronized
  releases.
- **Nx/Turborepo build orchestration** — deferred; pnpm recursive scripts
  and tsc project references are sufficient at this scale, and adding a
  build platform now is premature complexity.

# Consequences

- Positive: compiler-enforced architecture; per-package contract tests;
  trivially replaceable adapters.
- Negative: more package.json/tsconfig plumbing; contributors must
  understand workspace protocols (`workspace:*`).

# Implementation Notes

- Root `tsconfig.json` holds project references; each package references
  only the packages it depends on.
- Per-package tests run via `vitest --root ../.. --project <name>` so the
  root workspace config is authoritative.

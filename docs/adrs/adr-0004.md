# Context

Autonomous runs fail in messy ways: models stop emitting tool calls without
finishing, processes crash mid-run, humans must intervene, budgets run out.
Two ambiguities must be eliminated: *what state is a run in* (for recovery,
UI, and idempotency) and *when is an agent actually done* (text output is not
completion).

# Decision

1. Runs move through an explicit state machine
   (`QUEUED → PREPARING → RUNNING → WAITING_FOR_* → VERIFYING →
   COMPLETED | FAILED | BLOCKED | CANCELLED`) with a centrally validated
   transition table; illegal transitions throw. Failed/blocked/cancelled runs
   may be re-queued; completed is terminal.
2. Agent completion is explicit: the native runtime injects protocol tools —
   `complete_goal(outcome, summary)` and `request_human_input(reason)` — and
   only those calls (or budget/policy/cancellation enforcement) terminate a
   session. Text-only turns get one nudge toward the protocol; repeated
   text-only turns end as `GOAL_BLOCKED`, never as silent success.
3. Terminal agent outcomes are a closed set: `GOAL_COMPLETED`,
   `GOAL_BLOCKED`, `BUDGET_EXHAUSTED`, `POLICY_BLOCKED`,
   `HUMAN_INPUT_REQUIRED`, `FATAL_FAILURE`, `CANCELLED`, with a total
   mapping onto run states.

# Rationale

- A validated transition table turns "how did the run get here?" from
  archaeology into an event log query, and makes crash recovery decidable
  (non-terminal states are interruptions by definition).
- Tool-based completion forces the model to commit to an outcome and
  produce a standalone final report, which downstream steps (review,
  delivery, transitions) consume.
- A closed outcome set lets workflows and UI branch on semantics rather
  than parsing prose.

# Alternatives Considered

- **Heuristic completion (stop when the model stops calling tools)** —
  conflates "done", "confused", and "gave up"; rejected.
- **Structured-output final message instead of a tool** — works only for
  providers with reliable structured output; the tool approach uses the
  same mechanism as all other agent actions.
- **Free-form status strings** — stringly-typed state was explicitly ruled
  out by the engineering principles.

# Consequences

- Positive: deterministic recovery, precise UI, testable semantics
  (transition table and outcome mapping are unit-tested).
- Negative: external agent providers (Claude Code, Codex) don't speak our
  protocol tools; their adapters must map native completion signals onto
  the outcome set — an accepted per-adapter translation cost.

# Implementation Notes

- packages/core/src/run.ts holds the transition table;
  packages/runtime/src/protocol.ts the protocol tools.
- The nudge budget (`maxTextOnlyTurns`) and policy-denial budget
  (`maxPolicyDenials`) are runtime options, not magic constants.

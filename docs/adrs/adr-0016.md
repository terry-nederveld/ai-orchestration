# Context

An independent security review of the complete v1 codebase found five
compounding must-fix weaknesses: shell command injection through workflow
variable interpolation (work-item titles are attacker-controlled), secret
values reaching the persisted event log and SSE stream unredacted,
attribution policy enforced only on one commit path, full daemon
environment inherited by workspace commands, and a permission preset that
silently overrode a configured default-deny posture.

# Decision

1. **Command interpolation is env-var-indirect.** `${{ … }}` placeholders
   in workflow `command:` strings are replaced with quoted references to
   generated environment variables (`"$OVERTURE_VAR_n"`) whose values are
   passed via the spawn environment, never spliced into shell text. Shell
   metacharacters in work-item-derived values are inert by construction,
   regardless of how the author quoted the placeholder.
2. **Redaction covers every sink.** The `SecretRedactor` (which also
   tracks base64/URI/JSON-escaped forms) is applied to console logs, every
   event before it is persisted to the event log or delivered to SSE
   subscribers, and session snapshots before they are saved.
3. **Attribution policy enforced at the delivery choke point.** `push()`
   validates the messages of every outgoing commit against the
   attribution/watermark policy — commits created by agents through raw
   `git commit` can no longer bypass the check, because nothing reaches a
   remote except through the source-control provider.
4. **Workspace commands get an allowlisted environment.** Spawned
   commands receive PATH/HOME/locale-class variables plus explicitly
   passed values only; the daemon's ambient environment (operator API
   keys, cloud credentials) is never inherited.
5. **Permission presets respect operator intent.** The workspace-coding
   allow preset applies only when explicitly configured
   (`permissions.preset: workspace-coding`) or when the operator
   configured no permissions at all; any explicit permissions
   configuration disables the implicit preset so `defaultEffect: deny`
   means deny.
6. **Untrusted content is framed.** Work-item text is wrapped in explicit
   external-content markers in agent context, and MCP tool output is
   prefixed as data-not-instructions; MCP tools carry explicit policy
   targets (`mcp:<server>:<tool>`) via the `Tool.policyTarget` hook.
7. Supporting fixes: timing-safe control-plane token comparison, strict
   id charset validation on HTTP route parameters, symlink-resolved path
   containment in filesystem tools, full-UUID run/session ids.

# Rationale

The five findings compound into one attack chain (prompt injection →
unconstrained exec → env exfiltration, with delivery-policy bypass); each
decision removes a link structurally rather than patching an instance.
Env-var indirection was chosen over shell escaping because escaping cannot
compose safely with author-controlled quoting contexts.

# Alternatives Considered

- **POSIX shell-escaping interpolated values** — insufficient: values
  substituted inside author double-quotes still expand `$`/backticks.
- **Forbidding variables in command steps** — safe but crippling;
  indirection keeps the ergonomics.
- **Redacting only at the console logger** — the reviewed state;
  rejected as it protected the least important sink.

# Consequences

- Positive: the review's must-fix chain is closed; the remaining accepted
  risks are documented (extensions run unsandboxed in-process — a stated
  ADR-0014 trust decision that operator docs now state plainly; macOS
  keychain writes pass values via argv, ps-visible transiently —
  documented platform gap, keyring-binding upgrade planned).
- Negative: allowlisted environments can break builds that expected
  operator variables (e.g. JAVA_HOME); such variables must be passed
  explicitly via step `env:` — documented behavior change.

# Implementation Notes

- packages/workflow (interpolation), packages/secrets (redactor),
  packages/server (redaction pipeline, auth), packages/scm-git (push
  validation), packages/tools (env allowlist, symlink containment),
  packages/policy + packages/config + packages/cli (preset semantics).

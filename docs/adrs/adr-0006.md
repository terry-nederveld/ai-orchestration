# Context

The UI, persistence (event log), hooks, and notifications all need to know
what the orchestrator is doing, but none of them may couple to the runtime's
internals. Meaningful occurrences span work discovery, claiming, workspace
lifecycle, run state changes, workflow steps, model requests, tool calls,
sub-agents, budget thresholds, and approvals.

# Decision

All meaningful occurrences are published as a typed, discriminated-union
`OrchestratorEvent` on an in-process `EventBus` port. Consumers subscribe
with type/run filters. The default implementation is a synchronous fan-out
with handler isolation (a throwing subscriber cannot disrupt the publisher
or other subscribers). The event log persistence, the UI stream, and hook
dispatch are all bus subscribers, not runtime call sites.

# Rationale

- A closed event union is compile-time-checked documentation of everything
  observable; adding an event is an explicit contract change.
- Bus decoupling means the runtime never imports UI, persistence, or
  notification code — enforced by package boundaries.
- In-process is sufficient for the single-machine v1; the port shape
  (publish/subscribe with filters) maps directly onto a future
  network-transparent stream for remote control planes.

# Alternatives Considered

- **Direct callbacks/listeners on each subsystem** — N×M wiring and no
  uniform audit trail; rejected.
- **External broker (Redis/NATS) now** — premature enterprise complexity;
  explicitly deferred, enabled later by swapping the EventBus adapter.
- **EventEmitter with string topics** — stringly-typed; rejected.

# Consequences

- Positive: uniform audit trail (append-only event log), replayable run
  timelines in the UI, hooks without runtime coupling.
- Negative: synchronous fan-out means a slow subscriber slows publishing;
  subscribers must be fast or queue internally (the persistence subscriber
  batches).

# Implementation Notes

- packages/core/src/events.ts (union + port),
  packages/core/src/event-bus.ts (default implementation).
- Agent-session events are wrapped (`{ type: 'agent', event }`) so the
  session stream and the bus share one vocabulary.

# Context

MCP is a required integration mechanism (tools from external servers,
configured globally/per-project/per-workflow). The spec landscape in August
2026 is split: revision 2026-07-28 is a largely backward-incompatible
overhaul (stateless protocol, MRTR replacing server-initiated requests,
deprecated SSE transport and sampling/roots/logging), while the vast
majority of deployed servers still implement 2025-11-25 or 2025-06-18.

# Decision

- Integrate MCP as a client through the official `@modelcontextprotocol/sdk`
  (TypeScript), supporting stdio and Streamable HTTP transports, targeting
  the protocol revisions the SDK negotiates (the deployed-stable line,
  2025-11-25/2025-06-18), and adopting 2026-07-28 when the SDK and the
  server ecosystem do.
- MCP servers are configuration (`mcp.servers` with global/project/workflow
  scope), surfaced to agents as a ToolProvider whose tools pass through the
  same permission checks as built-ins. MCP servers are NOT application
  extensions — extensions are trusted local code with manifests; MCP servers
  are external processes/endpoints treated as untrusted tool sources.
- Remote-server auth uses the SDK's OAuth helpers; tokens live in the
  secret store.

# Rationale

- The official SDK owns version negotiation — chasing the newest spec
  revision by hand would strand us against the deployed server ecosystem.
- Routing MCP tools through the ToolRegistry/permission pipeline means
  hostile MCP tools meet the same policy wall as everything else.

# Alternatives Considered

- **Implement the protocol directly against 2026-07-28** — bleeding-edge
  with minimal server compatibility today; rejected for now.
- **Treat MCP servers as extensions** — conflates trust models; rejected.

# Consequences

- Positive: broad server compatibility; uniform permissioning; scoped
  configuration.
- Negative: 2026-07-28 features (MRTR, CIMD auth) arrive only with SDK
  support; documented as a known limitation.

# Implementation Notes

- packages/extensions hosts the MCP client integration as a ToolProvider;
  config schema already carries `mcp.servers` (packages/config).

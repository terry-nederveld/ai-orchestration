# Context

Credentials (API keys, tracker tokens, OAuth tokens) must live in secure OS
storage where available, never in plaintext config or database rows, and
never in model context or logs. Research: `keytar` is dead; the modern Node
binding is `@napi-rs/keyring` (native module); Electron offers safeStorage;
Tauri has Stronghold/community keyring plugins.

# Decision

`SecretProvider` implementations, resolved by platform at daemon start:

- macOS: Keychain via the `security` CLI (generic passwords under one
  service).
- Linux: Secret Service via `secret-tool` when installed (values piped over
  stdin, never argv).
- Fallback (Windows in v1, headless Linux, missing tools): AES-256-GCM
  encrypted vault file with a locally stored 0600 key file — protection
  equivalent to an SSH private key, documented as such.

Config files reference secrets by name only. A `SecretRedactor` scrubs
tracked values from all log output. Tools receive secrets through a
side-channel resolver (env injection into subprocesses), never through
model-visible content.

# Rationale

- CLI-based access keeps the daemon free of native npm modules (same
  packaging rationale as ADR-0010); the CLIs are first-party OS components.
- The port makes upgrading Windows to Credential Manager (via
  `@napi-rs/keyring` or a Tauri-side bridge) a drop-in adapter, planned
  post-v1 and documented as a limitation until then.

# Alternatives Considered

- **`@napi-rs/keyring` everywhere** — best-in-class coverage (incl.
  Windows) but reintroduces a native dependency into every install; chosen
  as the designated upgrade path rather than the v1 default.
- **Electron safeStorage / Tauri Stronghold** — ties secret storage to the
  shell; secrets belong to the daemon (headless mode must work).

# Consequences

- Positive: zero native deps; real OS keychain on macOS/Linux desktop;
  honest documented fallback elsewhere; redaction everywhere.
- Negative: Windows v1 uses the encrypted-file fallback (flagged in docs
  and in the security review); `security`/`secret-tool` absence silently
  downgrades to the fallback — surfaced via provider id in diagnostics.

# Implementation Notes

- packages/secrets; platform resolution in platform.ts; keychain service

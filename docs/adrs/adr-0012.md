# Context

The desktop shell must package for macOS/Windows/Linux with installers,
auto-update, tray, notifications, and low resource use — while the entire
product logic already lives in a Node daemon (ADR-0011). Research compared
Tauri v2.11 (GA since 2024; official Node-sidecar documentation; official
plugins for updater/notifications/tray/single-instance/autostart; native
webview; ~30–40MB idle RAM, <10MB installers) against Electron v42 (very
mature; bundles Chromium; 100MB+ installers; safeStorage built in) and
briefly Wails v3 (still beta) and Flutter (non-web UI stack).

# Decision

Use Tauri v2 for the desktop shell. The Overture daemon ships as a bundled
sidecar (Node runtime + bundled JS, `externalBin`), supervised by a small
Rust layer (spawn, health-check the HTTP API, restart on crash, graceful
shutdown on quit). The webview UI talks to the daemon's loopback API — the
same surface the CLI uses — not to Tauri IPC, except for shell concerns
(window, tray, notifications, updater, opening the token from disk).

# Rationale

- Because ADR-0011 moved all product logic into the daemon, the shell is
  genuinely thin — Tauri's smaller ecosystem is a non-issue since we need
  only its shell plugins, and its footprint advantage (native webview, tiny
  installers) directly serves the low-resource requirement.
- Rust is already in the environment and the sidecar supervision layer is
  small, bounded code.
- Secrets stay in the daemon (OS keychain via @overture/secrets), so
  Tauri's credential-plugin gap is irrelevant.

# Alternatives Considered

- **Electron** — the safe default, and what Docker Desktop uses; rejected
  because our thin-shell architecture neutralizes Electron's main advantage
  (deep Node integration in the shell) while keeping its costs (Chromium
  footprint, larger installers).
- **Wails v3** — pre-1.0 beta; too risky as a foundation.
- **Flutter desktop** — abandons the web-tech UI skill set and shares no
  code with any future web deployment.

# Consequences

- Positive: <10MB-class installers for all three platforms via the built-in
  bundler (dmg, msi/nsis, deb/rpm/AppImage); official updater plugin.
- Negative: sidecar lifecycle management is hand-rolled (Tauri has no
  built-in supervisor — known gap, tracked in plugins-workspace #3062);
  native-webview rendering differences must be smoke-tested per platform.
- Risk accepted: if Tauri becomes a blocker, the thin-shell design makes an
  Electron fallback a packaging change, not a rewrite.

# Implementation Notes

- apps/desktop: Tauri config, Rust sidecar supervisor, web UI.
- UI is built from reusable components consuming the daemon API + SSE.

# Context

Concurrent runs must never mutate each other's working directories. Options
range from cheap (worktrees off a shared clone) to heavy (containers, remote
sandboxes). Symphony's workspace invariants (path containment, sanitized
naming, cwd enforcement) proved effective for the same problem.

# Decision

`WorkspaceProvider` is a strategy port with four v1 implementations:
git-worktree (default), git-clone, local-directory, temp-directory. The
worktree strategy keeps one shared base clone per repository (creation
serialized per repo to prevent double-clone races) and adds a per-run
worktree on a fresh `overture/<slug>` branch. Every path segment derived
from caller-controlled values (run ids, branch names, repo locators) is
slugified and containment-checked. Cleanup honors retention policy
(always / on-failure / never). Container and remote strategies are future
implementations of the same port.

# Rationale

- Worktrees give real filesystem isolation between runs at near-zero cost
  (shared object store, instant creation) — the right default for one
  machine.
- Strategy-as-port means containers/remote runners arrive without touching
  the orchestrator.

# Alternatives Considered

- **Fresh clone per run as default** — simplest mental model but slow and
  disk-hungry on large repos; retained as an opt-in strategy.
- **Containers in v1** — real isolation for hostile code but heavy setup
  cost and platform friction; explicitly deferred, enabled by the port.

# Consequences

- Positive: concurrent runs verified isolated by test; collision-safe paths.
- Negative: worktrees share git config/hooks with the base clone; hostile
  repository content is mitigated by policy/permission checks rather than
  OS-level isolation until a container strategy exists (tracked for the
  security review).
